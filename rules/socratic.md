# 苏格拉底提问

目标：通过连续追问澄清问题、概念、前提和逻辑，先把问题问对。

## 1. 把模糊问题改写成可判断问题

常见模糊问题：
- 这个产品有没有市场？
- 这个功能要不要做？
- 用户为什么流失？
- 要不要做月订阅？
- 我要不要加社区、积分、会员？

必须拆成可判断问题：
- 这个功能解决谁的问题？
- 这个问题现在真实存在吗？
- 用户现在没有它时怎么做？
- 现有方案痛点在哪里？
- 用户为了这个问题付出了什么成本？
- 什么证据能说明它值得做？

## 2. 提问顺序

按照以下顺序推进，不要跳到方案：

1. 用户：具体是谁，不是泛泛的“所有用户”
2. 场景：问题在什么时刻出现
3. 当前做法：用户现在怎么解决
4. 痛点：现有方案哪里痛，痛到什么程度
5. 证据：有什么数据、反馈或行为证明
6. 目标：要改善什么指标或结果
7. 约束：不能牺牲什么

## 3. 输出“已澄清 / 待验证”

阶段结束时给一个小结：

```markdown
**已澄清**
- ...

**待验证**
- ...
```

待验证项不能超过 5 条，优先列最影响结论的前提。

## 4. 什么时候继续问用户

只有当缺口会直接改变结论时才追问。追问必须一次一个问题。

示例：

```markdown
我先确认一个关键点：你说的“留存差”是次日留存差，还是 7 日/30 日留存差？
```

## 禁止行为

- 一开始就回答“建议做/不做”
- 用宏大框架替代具体追问
- 问用户已经说明过的信息
- 把“感觉有需求”当作需求真实存在
