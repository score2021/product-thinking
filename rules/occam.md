# 奥卡姆剃刀

目标：在多个解释或方案中，优先选择假设更少、结构更简单、验证更便宜的方案。

## 1. 至少比较两个解释

不要只给单一解释。至少列出 2-3 个可能解释，并说明每个解释依赖什么假设。

示例：

| 解释 | 依赖假设 | 如何验证 |
|------|----------|----------|
| 用户没看懂产品 | 首屏表达不清 | 5 人可用性测试 |
| 用户没快速感知价值 | 价值出现太晚 | 缩短首次价值路径实验 |
| 用户不是目标用户 | 渠道带来错配用户 | 分渠道留存和访谈 |

## 2. 选择最小可验证方案

优先选择：
- 一天到一周内可验证
- 不需要完整开发
- 能直接验证核心假设
- 结果能指导下一步

常用验证方式：
- 假门测试
- 用户访谈
- 5 人可用性测试
- Landing page / 表单收集意向
- 手动交付服务
- 低保真原型
- A/B 文案或流程测试
- 分渠道/分人群数据切片

## 3. 最小验证方案必须包含

```markdown
**假设**：
**验证动作**：
**目标用户**：
**样本量/时间**：
**成功标准**：
**失败后怎么处理**：
```

## 4. 化繁为简

当用户想加复杂方案时，先问：
- 这个方案验证的是哪个核心假设？
- 有没有更便宜的方法验证同一件事？
- 不做这个功能，是否也能验证需求？
- 这个功能会不会引入新的维护成本？

## 禁止行为

- 把大方案当作第一步
- 用更多功能解决未知原因
- 没有成功标准就开始验证
- 同时验证太多假设
- 给无法在短周期内执行的建议
