# 第一性原理

目标：从底层事实和用户价值出发，不依赖行业惯例、竞品做法或表面经验。

## 1. 区分四类信息

分析时必须区分：

| 类型 | 说明 |
|------|------|
| 事实 | 已经观察到的数据、行为、反馈 |
| 假设 | 还没验证但当前判断依赖它 |
| 习惯 | 行业常见做法、团队默认做法 |
| 推断 | 基于事实和假设得到的判断 |

## 2. 回到产品卖的是什么

必须回答：
- 用户买的是工具、结果、效率、确定性，还是风险降低？
- 价值是持续发生，还是一次性发生？
- 用户是否需要反复回来？
- 不用这个产品，用户损失什么？
- 如果只保留一个价值承诺，它是什么？

## 3. 订阅/付费判断规则

遇到月订阅、会员、SaaS 定价等问题时，按以下维度拆：

1. 产品是否持续被使用
2. 价值是否持续发生
3. 用户是否高频打开
4. 用户是否每天/每周离不开
5. 付费动机是持续依赖，还是某一刻省下大量成本

如果产品是一次性解决问题，默认不先做月订阅；除非能证明持续价值或持续服务成本。

## 4. 功能判断规则

遇到“功能要不要做”时，先判断：
- 它解决的是核心问题还是边缘问题
- 没有它用户是否无法完成关键任务
- 它是否会让系统更复杂
- 它是否能被更轻量的流程、文案、默认值或人工方式替代
- 它是否可先用假门、手动服务、低保真原型验证

## 5. 留存/流失判断规则

遇到留存差或流失问题时，优先拆成：
- 用户没看懂产品解决什么问题
- 用户没有快速感知价值
- 吸引来的用户不是目标用户
- 产品确实解决低频或一次性问题
- 关键体验或交付结果不达标

不要直接归因于“功能太少”。

## 禁止行为

- “竞品都做”作为主要理由
- “行业一般这样”作为结论
- 不拆事实和假设
- 不判断价值发生频率就建议订阅
- 不找真实流失原因就建议加功能
